# 🛠️ Server Monitor Bot (Telegram) — Полная документация

## 📌 1. Общее описание проекта
**Server Monitor Bot** — это автономный инструмент на Python для непрерывного мониторинга и удаленного администрирования локального Windows-сервера. Бот объединяет в себе функции системного аналитика, сетевого диагноста и «цифрового сторожа» (Watchdog). 

Бот спроектирован для работы как в личных сообщениях с администратором, так и в **специализированных Telegram-группах**, обеспечивая прозрачность состояния сервера и оперативное оповещение обо всех сбоях для всей команды разработчиков.

---

## ⚙️ 2. Стек технологий и зависимости
Для обеспечения стабильной, отказоустойчивой и легковесной работы используются следующие компоненты:
* **Python 3.10+**: Основной язык разработки.
* **pyTelegramBotAPI (telebot)**: Взаимодействие с Telegram Bot API через синхронный Long Polling.
* **psutil**: Кроссплатформенная библиотека для глубокого анализа системных ресурсов (процессы, память, ядра, дисковое пространство).
* **subprocess, os, urllib**: Встроенные модули для выполнения команд ОС (ICMP-пинг) и проверки HTTP-доступов (выявление блокировок API).
* **python-dotenv**: Безопасная подгрузка токена бота из скрытого файла окружения.
* **json (built-in)**: Формат для хранения настроек, путей к логам, сетевых адресов и прав доступа.

## 🚀 3. Функциональные модули

### 📊 3.1. Ресурсы и «Железо» (System Health)
Бот анализирует состояние сервера и предоставляет данные в удобном виде:
* **CPU (Процессор)**: Общий процент загрузки всех ядер.
* **RAM (Оперативная память)**: Объем использованной и свободной памяти.
* **Disk Monitor (Мониторинг дисков)**: Контроль свободного места на системном (`C:\`) и пользовательском (`D:\`) дисках. Предотвращает остановку системы из-за переполнения.
* **Uptime**: Время работы сервера с момента последней загрузки Windows.

### 🌐 3.2. Сеть и API (Connectivity & Web Services)
Многоуровневая проверка связи сервера с внешним миром:
* **ICMP Ping (Маршрутизация)**: Проверка физической доступности узлов (например, `8.8.8.8`). Показывает, есть ли вообще интернет на сервере.
* **HTTP Checker (Анти-Блокировка)**: Умная проверка API-эндпоинтов (Telegram API, Gemini API). Бот имитирует браузерный запрос и анализирует HTTP-коды:
  * `200 OK` — Доступ открыт, API работает.
  * `403 Forbidden` — Провайдер, РКН или сам сервис заблокировал ваш IP (например, ограничения Gemini по региону).
  * `429 Too Many Requests` — Превышен лимит запросов к API.

### 🐕 3.3. Универсальный Watchdog (Сторож процессов)
Система автоматического слежения за критически важной инфраструктурой:
* **Скрипты** (`.py`, `.js`, `.bat`): Бот проверяет не только имя процесса, но и **аргументы командной строки**, чтобы точно идентифицировать работающий скрипт (например, `smart_bot.py`).
* **Приложения** (`.exe`): Прямой мониторинг баз данных и веб-серверов (`nginx.exe`, `redis-server.exe`).
* **Алиасы**: каждому паттерну можно задать понятное имя — оно показывается в отчёте и алертах вместо сырого имени файла.
* При падении процесса генерируется экстренный алерт.

### 📁 3.4. Дистанционная работа с логами (Log Management)
* **Команда `/getlogs`**: Бот сканирует конфигурационный файл, собирает указанные файлы логов и отправляет их в чат в виде документов (`.log` или `.txt`). Позволяет анализировать ошибки без RDP-доступа к серверу.

## 🎛️ 4. Система конфигурации и Групповой режим

### 🔑 4.1. Секреты (Файл `.env`)
Шаблон — `env.example` (скопируйте в `.env`). **Файл `.env` должен быть добавлен в `.gitignore`.**
```env
BOT_TOKEN=123456789:ABCDefghIJKLmnopQRSTuvwxYZ
GEMINI_API_KEY=ваш_ключ_от_gemini_api
```
> ⚠️ Файл `.env` содержит секреты и не должен попадать в репозиторий (добавлен в `.gitignore`).

### 🗂 4.2. Конфигурация логики (Файл `config.json`)
Шаблон — `config_example.json`. Все поля проходят строгую валидацию через Pydantic.

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `admins` | `list[int]` | Telegram ID администраторов, которым разрешён доступ. |
| `target_chat_id` | `int` | ID чата для фоновых алертов и отчётов. `0` — отправлять первому админу. |
| `enable_group_only_mode` | `bool` | Режим «только группа»: команды принимаются только из `target_chat_id`. |
| `enable_http_checks` | `bool` | Тумблер раздела «API & Доступы» (HTTP-проверки). По умолчанию `false` (выключено). |
| `cpu_alert_percent` | `int` | Порог алерта по CPU (%). По умолчанию 85. |
| `ram_alert_percent` | `int` | Порог алерта по RAM (%). По умолчанию 85. |
| `disk_alert_percent` | `int` | Порог алерта по диску (%). По умолчанию 90. |
| `disks_to_watch` | `list[str]` | Диски для проверки (например, `["C:\\", "D:\\"]`). Пустой список — автоопределение. |
| `tcp_hosts` | `dict[str,str]` | Имя → `host:port` для проверки TCP-портов. |
| `alert_cooldown_sec` | `int` | Пауза между повторными алертами по одному источнику (сек). По умолчанию 300. |
| `intervals.watchdog_check_sec` | `int` | Интервал проверок Watchdog (сек). |
| `intervals.silent_report_sec` | `int` | Интервал тихих плановых отчётов (сек). |
| `intervals.planned_restart_sec` | `int` | Плановая самоперезагрузка (сек). `0` — выключено. |
| `ping_hosts` | `dict[str,str]` | Имя → адрес для ICMP-пинга. |
| `http_hosts` | `dict[str,str]` | Имя → URL для HTTP-проверки (работает только при `enable_http_checks: true`). |
| `processes_to_watch` | `dict[str,str]` | Паттерн → алиас для Watchdog. Ключ — что искать (имя процесса/скрипта), значение — понятное имя в отчёте. |
| `log_files` | `dict[str,str]` | Имя → путь к файлу лога для команды `/getlogs`. |

## 🕹️ 5. Команды бота

| Команда | Описание |
| :--- | :--- |
| `/start` | Проверка авторизации и приветствие. |
| `/help` | Подробная справка по всем командам. |
| `/status` | Полный срез состояния сервера (CPU, RAM, диски, ping, TCP-порты, Watchdog с CPU/RAM, опционально API). |
| `/getlogs [N]` | Отправка файлов логов из `log_files`; `/getlogs 200` — последние 200 строк. |
| `/ping` | Healthcheck: uptime бота и статус фонового монитора. |
| `/reboot` | Удалённая перезагрузка Windows (двухшаговое подтверждение: `/reboot` → `/reboot confirm`). |
| `/reload` | Перечитать `config.json` без перезапуска бота. |

Команды `/start` и `/help` выводят инлайн-меню с кнопками быстрого доступа (Статус, Логи, Перезагрузка, Reload).

Все команды требуют, чтобы пользователь был в `admins`; при включённом `enable_group_only_mode` — ещё и выполнение из `target_chat_id`.

## 🔄 6. Фоновый цикл (Watchdog + отчёты)

В отдельном потоке (`background_loop`) непрерывно выполняется:

1. **Watchdog** — каждые `watchdog_check_sec` проверяет `processes_to_watch`. При падении процесса шлётся экстренный алерт, при восстановлении — «отбой тревоги». Память о падениях хранится в `set`, чтобы не спамить.
2. **TCP-порты** — проверяет доступность `tcp_hosts`; недоступен → алерт, снова доступен → «отбой».
3. **Алерты по ресурсам** — каждую итерацию проверяются CPU/RAM/диски против порогов `cpu_alert_percent`/`ram_alert_percent`/`disk_alert_percent`. При превышении — алерт, при возврате в норму (с гистерезисом −5%) — «отбой тревоги».
4. **Тихий отчёт** — каждые `silent_report_sec` отправляется полный срез с `disable_notification=True`.
5. **Плановый рестарт** — через `planned_restart_sec` скрипт завершается через `os._exit(0)`, а `run_monitor.bat` поднимает его заново.

Все алерты имеют cooldown (`alert_cooldown_sec`) — повторное сообщение по одному источнику не шлётся раньше истечения паузы (анти-флаппинг).

## 🔒 7. Безопасность

* `.env`, `config.json` и `*.log` добавлены в `.gitignore` — секреты и логи не попадают в репозиторий.
* Доступ ограничен списком `admins` + опциональным групповым режимом.
* Перезагрузка `/reboot` требует явного подтверждения (`/reboot confirm`) в течение 30 секунд.

---

## 🚀 8. Запуск 24/7 (Windows)

Используйте `run_monitor.bat` вместе с Планировщиком задач (запуск от имени `SYSTEM`, триггер «При запуске», рабочая папка — корень проекта). Bat-файл автоматически перезапускает скрипт при падении. Дополнительно сам бот переподключается к Telegram при обрыве сети (long polling с бэкоффом) и корректно завершается по SIGINT/SIGTERM.
